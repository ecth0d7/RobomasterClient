# 核心状态簿与遥测管理插件 (core)

## 插件定位与接口角色
`core/` 目录实现客户端底层状态管理与时间序列对齐存储引擎，导出原生插件 ID 为 **`state.telemetry`**，实现系统 `ExtensionPlugin` 接口，角色定义为 `role: "state"`。**本插件为系统随启动载入的核心状态管理扩展，负责规范化已接收遥测数据的时效性、单调版本控制及显示边界记录**。


## 依赖与启用条件
- **系统依赖**：纯 Qt Core 原生架构，无第三方网络或图形库依赖。
- **加载入口**：随客户端启动显式加载，参数为 `--state-plugin=state.telemetry`（系统默认值）。作为核心原生服务，其端点与实例在启动时固化，**运行期间更换实现必须重启客户端**。

## 配置字段说明
`state.telemetry` 作为核心遥测归一化引擎，自身无需复杂的业务参数，在启动配置中遵从规范格式挂载：

| 字段名 | CLI 选项 | 默认值 | 约束与说明 |
| :--- | :--- | :--- | :--- |
| `state-plugin` | `--state-plugin` | `state.telemetry` | 指定状态存储管理插件 ID |

在启动配置文件 Profile 中，支持在 `plugins.state` 中预留受限对象，但内部无额外需手工指定的外部选项。

### 最小启动命令
```bash
./RoboMasterMqttTest --state-plugin=state.telemetry
```

## 使用与状态判断
- **业务运转机制**：本插件在后台接收各网络与协议层解码后的数据字段，维护全局版本号 `m_revision`，并跟踪逐字段新鲜度与接收时间差（`ageMs`）。
- **判断运行正常**：
  1. 前端 UI 组件绑定的属性变化信号（`contextRevision`）能够随着下位机状态更新而正常重绘；
  2. 针对包含机器人身份/阶段边界的上下文变动，状态簿能准确触发分发并隔离历史数据。

## 缺失、断连与边界保护
- **断连保护机制**：当下游网络断开连接时，状态簿中保留历史快照供界面查看，但字段新鲜度标志将随时间超时置为失效，防止各决策子系统依据陈旧遥测进行误判。

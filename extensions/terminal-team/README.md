# 队伍语义共享与聚合插件 (extensions/terminal-team)

## 插件清单与架构定位
本目录提供一套基于 Schema 3 语义契约的可选队伍协同聚合插件，实现 `ExtensionPlugin` 接口，角色定义为 `terminal-team`：
- `terminal.team.aggregate.v3`：支持固定对端节点（Pinned Nodes）与 mTLS 加密传输的队伍态势聚合组件。

本插件属于项目自定义的数据共享实现，不冒充官方裁判系统通信协议。其网络与比赛官方 MQTT 隔离，用于队员之间授权传递派生观测。

## 依赖与启用条件
1. **运行依赖**：依赖本机的 mTLS 网络链路和证书。私钥由系统环境变量解析，严禁明文暴露。
2. **启用入口**：
   - 在专用终端壳层的队伍配置页完成提供者、身份、权限和证书设置，再显式启用。普通2026插件管理页不是此插件的入口；2027场地模型也不依赖它。
   - 启用对象实例并不等于已成功连通后端网络，需要所有节点证书握手成功且时钟同步后方可建立连接。

## 配置字段说明
配置支持严格字段检查，不支持任意额外未知字段：

| 字段名 | 类型 | 默认值 | 约束说明 |
| :--- | :--- | :--- | :--- |
| `schema` | 整数 | `3` | 协议版本号，严格固定为 3 |
| `context` | 对象 | `{}` | 严格含 `profile_id`、`field_profile_id`、`capability_revision`，来自当前宿主；本实现的Profile为 `rmuc2027-regional-v1.0.0` |
| `team_id` | 字符串 | 无 | 队伍标识（ASCII 字符），必填 |
| `match_id` | 字符串 | 无 | 比赛场次标识，必填 |
| `epoch` | 字符串 | 无 | 共享轮次标识，重启或换场须更迭，防止重放 |
| `node_id` | 字符串 | 无 | 本机节点标识，必填 |
| `robot_key` | 字符串 | 无 | 语义机器人键（如 `red/infantry/1`），非物理线路编号 |
| `publisher_id` | 字符串 | `""` | 聚合发布者节点 ID，允许为空或指定节点 |
| `can_send` | 布尔 | `false` | 本节点是否允许发送数据 |
| `can_aggregate` | 布尔 | `false` | 本节点是否允许执行聚合切片计算 |
| `allowed_fields` | 列表 | `[]` | 本节点允许输出的观测字段及对应用途白名单 |
| `allowed_uses` | 列表 | `[]` | 允许的用途列表，比赛环境严禁包含 `externalAi` |
| `clocks_synchronized` | 布尔 | `false` | 本地声明时钟是否已对齐 |
| `max_clock_skew_ms` | 整数 | `250` | 允许的最大时钟偏移（0–1000 毫秒） |
| `heartbeat_ms` | 整数 | `1000` | 心跳保活周期（毫秒） |
| `timeout_ms` | 整数 | `3000` | 消息超时（毫秒），必须大于等于 3 倍心跳 |
| `training_mock` | 布尔 | `false` | 是否包含测试模拟数据，正式比赛环境下强制为 `false` |
| `ca_file` | 字符串 | 无 | CA 证书文件路径 |
| `certificate_file` | 字符串 | 无 | 客户端证书文件路径 |
| `signing_key_file` | 字符串 | 无 | 内部参数：由宿主解析环境变量后提供的私钥文件路径，不在操作员配置中直接填写 |
| `endpoint` | 字符串 | 无 | 显式 `mqtts://host:port`，不含账号、路径、查询串或片段 |
| `team_wide_sharing_confirmed` | 布尔 | `false` | 全队共享边界须明确确认 |
| `peers` | 列表 | `[]` | 明确指定的对端节点列表，最多 15 个（总节点上限 16） |

## 最小配置与使用示例
本插件内部配置严格要求上表字段及完整当前宿主上下文，不提供可脱离宿主粘贴的精简JSON。操作员在专用终端队伍配置页选择 `terminal.team.aggregate.v3`，填写队伍、比赛、轮次、本机语义机器人键、显式mTLS端点、CA/本机证书与私钥路径环境变量引用，并固定每个对端的证书指纹和逐字段用途授权。证书文件、对端白名单、时钟同步及全队共享确认均齐备后才启用。缺少这些条件时保持停用。

`allowed_fields` 的逐字段授权和 `allowed_uses` 的总用途许可共同限制转发；本页列的是插件内部参数，不能直接套入普通2026的 `TeamConfiguration`。

**使用与状态判断**：
在专用终端队伍配置页启用后，观察状态字段：
- `active: true` 且 `connected: true` 表示链路握手成功。
- 检查接收/接受计数、当前视图的 `view_id` 与来源、时效；不能仅凭服务已启用判断接收或聚合成功。

## 停用、缺失与异常处理
- **比赛环境越界**：在比赛环境（`competition`）下将 `training_mock` 设为 `true` 或包含 `externalAi` 用途，配置直接报错拒绝装载。
- **轮次复用**：若重复使用已结束的 `(team_id, match_id, epoch, node_id)` 组合，系统拒绝加载并提示必须更换轮次纪元。
- **网络断连**：状态降级为 `offline`，所有来自对端的临时状态在达到超时时间后标记为过期，不影响本地控制。

关于 Schema 3 证明验证及权限窄化机制，请查阅 [TECHNICAL.md](../../docs/TECHNICAL.md)。

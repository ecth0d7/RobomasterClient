# 统一插件配置与文档交付契约 (plugins/CONFIGURATION_CONTRACT.md)

## 1. 适用范围与交付准则

本契约适用于 RobomasterClient 项目内新维护的所有核心端点、可选插件目录及宿主支持库。所有模块必须包含规范的 `README.md` 与配置说明，使使用者能够配置、启动、判断状态并处理常见故障。

- **文件放置规范**：源码、资源资产与配置模板必须保存在项目仓库内；外部测试工具、开发草稿、运行抓包及临时日志归档于项目外的 `ProjectSupport/<项目名>/tests|tools|examples|builds|results` 分类目录；正式技术文档图表统一归档至 `docs/media/` 目录下。
- **打包交付规范**：构建发布产物必须附带说明文档。对于含 `rmplugin.json` 的扩展包，打包清单（`FILES`）必须显式包含 `README.md`，不得在严格校验的 `rmplugin.json` 中添加未在 SDK 中定义的未知键（如 `documentation` 等）。打包体系保持对 `schema 1` 的完全兼容，缺少 README 的旧版扩展包仍可被宿主正常加载，本契约不变更现有 SDK 加载 ABI。

## 2. 插件类型与加载入口规范

交付文档必须明确插件架构类型及确切入口：
1. **QML 目录扩展（Directory-based QML Extensions）**：通过 QML `Loader` 动态加载，入口通常声明为 `qml/XXX.qml`（如 `extensions/battlefield-3d/manifest.json` 指定 `entry: "qml/Field3D.qml"`）。此类扩展在宿主层面必须具备懒加载能力，缺少依赖时可由宿主接管降级。
2. **原生端点／服务插件**：实现 `ClientPlugin` 或 `ExtensionPlugin` 的Qt动态库，由宿主选择和加载；写明插件ID、接口与启动参数。
3. **`rmplugin.json` 扩展包**：以QML入口装配，可选包含SDK原生工厂动态库。写明API版本、服务与通道；原生库另列工厂符号与生命周期。此类包与原生Qt插件不是同一种装载接口。
4. **宿主支持库**：没有独立插件ID或用户启停入口时明确说明，由哪个宿主提供配置。

## 3. README.md 必备技术字段与格式

每个插件根目录下的 `README.md` 必须系统性说明以下内容：

- **基础元数据**：明确声明插件 ID（如 `map.battlefield3d`）、插件角色（如 `map-renderer`）、版本号及是否支持赛中独立启停。
- **依赖项与环境**：列出图形环境要求（区分最低要求与实际测试版本）、Qt 模块依赖、硬件限制及系统库依赖。
- **启动与操作**：给出当前真实界面入口或命令、一个完整可运行示例；仅为内部参数或局部片段时明确标注，列出仍需提供的环境、证书和路径。说明如何观察实际成功，不能用“已启用”代替模型推理、后端连接或播放验证。
- **配置规范**：列出每个配置字段的命名空间、类型、默认值、合法取值范围及生效时机。若模块无独立配置项，必须明确注明“无独立配置项”。
- **安全与凭据管理**：**严禁在代码、配置文件或文档中硬编码敏感密钥**。所有认证凭据只允许通过环境变量引用或外部指定挂载文件获取。
- **运行生命周期与状态**：定义模块在启动成功、初始化失败、后端断连、数据超时（过期清退）以及文件缺失等边界工况下的标准表现与日志状态。核心模块对于模型与非关键服务应具备缺省容忍度，缺失时基础 MQTT/UDP 及常规 QML 渲染必须维持正常运转。
- **技术边界与取舍**：如实记录实现选型（如使用 Qt 壳层直载替代跨进程外部引擎的原因）与技术边界，区分已实现、实测、工程推论与尚未验证的内容；性能数字注明硬件、版本、输入和测量范围。适当说明未选替代方案的成本。

## 4. 插件配置示例（与代码严格对应）

以可选 QML 扩展 `map.battlefield3d` 为例，其仅使用 Qt Settings 进行展示层状态持久化，配置定义必须与源码严格对应：

```ini
[OptionalPlugins]
Battlefield3D\enabledMap=true
```

- **分类（Category）**：`OptionalPlugins/Battlefield3D`
- **键名**：`enabledMap`
- **类型**：`bool`
- **默认值**：`true`
- **作用域**：仅控制操作手在按 `M` 键展开大地图时是否拉起 3D 渲染器，不代表后端遥测已连接，不增加额外非代码支撑的 JSON 开关。

## 5. 文档与分发检查

源内README使用可移植的相对链接，必要截图与动图放在 `docs/media/`，运行时贴图、字体、模型及许可仍随实际扩展分发。构建将本项目模块指南复制到 `share/robomaster/plugin-guides/`，并保留技术手册、媒体和统一契约的相对目录，使脱离源码也能查阅。新增模块须同步该交付清单。

文档随配置字段、默认值、入口及生命周期变更一起更新；审阅时核对示例与真实参数，避免把不完整片段写成完整配置。正式用户文档不列开发验收服务器的名称、私有控制接口或搭建步骤，验收过程记录保留在项目外。详见 [技术手册第8章](../docs/TECHNICAL.md)。
